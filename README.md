# Stetwise by Ouroboros

Safe, reversible edits to Excel (`.xlsx`, `.xlsm`) and Word (`.docx`) for ChatGPT, Claude, Cursor, and Grok.

Every write is a preview first. Apply stores a new version only after the engine checks that untouched package parts kept their compressed bytes. Undo publishes an earlier version as a new head. If an edit cannot be done without risking formulas, styles, charts, pivot tables, shapes, comments, or tracked changes, Stetwise refuses it.

This repository does not deploy the service and does not create cloud accounts. `https://stetwise.app/mcp` in `server.json` is the planned address. It is not live. `stetwise.com` is a parked name and is not this product. Support: [ouroborosplugins@gmail.com](mailto:ouroborosplugins@gmail.com).

## Run locally

```bash
python3 -m pip install --user -r engine/requirements.txt
npm install
npm run build
STETWISE_DEV_AUTH=1 STETWISE_SIGNING_SECRET=change-me npm start
```

The dev bearer is `STETWISE_DEV_TOKEN` (default `dev-stetwise`). Dev auth is ignored when `NODE_ENV=production`. Leave `ENGINE_URL` unset to run the Python engine as `python3 -m stetwise` beside the server. Set `ENGINE_URL` and `ENGINE_HMAC_SECRET` to call the container instead.

```bash
docker build -f engine/Dockerfile -t stetwise-engine engine
docker run --rm -p 8080:8080 -e ENGINE_HMAC_SECRET=change-me stetwise-engine
```

The root `Dockerfile` is the Node image. It does not contain the Python engine. For a long-running HTTP process set `STETWISE_HTTP_ONLY=1` so a closed stdin does not also start the stdio transport. Set `ENGINE_URL` on that image. See Hosting below for the 25 MB file path.

```bash
curl -T ./model.xlsx "$UPLOAD_URL"
```

`start_upload` returns that URL. It is one-time and lasts 15 minutes. `export` returns a download link that lasts 15 minutes.

Checkout sends `line_items[0][price]` set to `STRIPE_PRICE_MONTHLY` or `STRIPE_PRICE_YEARLY`. It sets `subscription_data[trial_period_days]` to 14. It does not create a product or a price, and it does not send an amount. Stripe shows the amount. While `subscription_status` is `trialing`, the server enforces the trial caps below (100 applied edits, 20 recalculations, 200 proposals, and 200 reads), even if the Stripe plan name is already Pro. An `active` subscription uses the Pro caps. Past a cap the call is blocked. There is no overage charge.

Monthly caps, overridable without a code change:

| Variable | Default |
|---|---|
| `STETWISE_CAP_PRO_EDITS` | 1000 |
| `STETWISE_CAP_PRO_FILES` | 250 |
| `STETWISE_CAP_PRO_RECALCS` | 200 |
| `STETWISE_CAP_PRO_PROPOSALS` | 2000 |
| `STETWISE_CAP_PRO_READS` | 1000 |
| `STETWISE_CAP_PRO_MAX_BYTES` | 26214400 (25 × 1024 × 1024) |
| `STETWISE_CAP_TRIAL_EDITS` | 100 |
| `STETWISE_CAP_TRIAL_FILES` | 25 |
| `STETWISE_CAP_TRIAL_RECALCS` | 20 |
| `STETWISE_CAP_TRIAL_PROPOSALS` | 200 |
| `STETWISE_CAP_TRIAL_READS` | 200 |
| `STETWISE_CAP_TRIAL_MAX_BYTES` | 26214400 |
| `STETWISE_HEAD_CACHE_BYTES` | 67108864 |
| `STETWISE_RECALC_TIMEOUT` | 60 seconds |

Each started 5 MB of a file counts as one unit toward files, applied edits, recalculations, proposals, and reads. A 25 MB file counts as 5. A call that would pass the cap is blocked entirely. Trial file cap defaults to 25 new files per UTC month. Pro is 250. Trial reads default to 200 units per UTC month. Pro reads default to 1,000. A trialing subscription uses the trial caps. An active subscription uses the Pro caps, including a yearly plan. Counters are per user and per UTC month. Deleting a file does not refund that month's file count. Restore does not count as an applied edit. A recalculation counts when LibreOffice starts, whether it finishes or not. A refusal before LibreOffice starts (not a workbook, no formulas, or LibreOffice is missing) does not count. A proposal counts when it is saved. An unchanged recalculation does not save a proposal. `inspect`, `read`, `search`, `list_versions`, and `diff_versions` each count as one read of that file's units when the call succeeds.

Files expire 24 hours after last use. `set_retention` accepts 24 or 168 (7 days). `POST /internal/purge` with header `x-stetwise-purge` deletes expired rows and unreferenced blobs. `GET /internal/purge` with `Authorization: Bearer $CRON_SECRET` does the same call for Vercel Cron. Objects under `incoming/` and `stage/` younger than 2 hours are left in place. The route does not create cloud resources by itself.

## Persistence

Dev and tests use the local directory (`STETWISE_STORE=local`, or no Supabase keys). A container restart or a serverless instance does not keep that directory.

Hosted state uses the Supabase project you create. This repository does not create the project, the bucket, or any Stripe object.

1. Create a Supabase project and copy the project URL, anon key, and service role key into the host environment. The service role key stays on the server.
2. Open the SQL editor and run `supabase/schema.sql`. That creates `profiles`, `usage_monthly`, `files`, `file_versions`, `proposals`, `upload_nonces`, `audit_events`, and `support_requests`, plus the private Storage bucket `stetwise-files`. Running it again is safe: it updates the bucket in place. The bucket `file_size_limit` is 25 MiB (26214400 bytes). `support_requests` has row level security and no policies, so anon and authenticated roles have no access; the service role writes it. Stetwise functions pin `search_path` to `public, pg_temp`.
3. Run `supabase/oauth_resource_binding.sql` in the SQL editor. Running it again is safe and does not overwrite the resource setting. Then set that setting to the exact MCP URL, `APP_BASE_URL` plus `/mcp`, with https, no trailing slash, and no query or fragment:

```sql
update stetwise_private.settings
set value = 'https://YOUR_HOST/mcp'
where key = 'mcp_resource';
```

In the dashboard open Authentication → Hooks → Custom Access Token and choose `public.stetwise_access_token_hook`. The script grants `supabase_auth_admin` select on `auth.oauth_authorizations`. The hook reads that table as that role. The hook adds the configured URL to `aud` (keeping `authenticated`, so `aud` is an array) only for an OAuth token when every open (approved, unexpired) authorization for that client and user normalizes to that exact URL. Scheme and host case are normalized. One open authorization for another host (`https://evil.example/mcp`), another path, a trailing slash, `http://`, a query, a fragment, or no resource leaves `aud` as `authenticated`, and `/mcp` rejects the token. An older row in `stetwise_private.oauth_resources` is used on refresh only after this rule has written it. First-party session tokens are not changed. Disconnect and connect clients again after enabling the hook.

Supabase does not attach a code to its authorization, and an approval stays open for about 10 minutes. A code issued with no resource can still be bound when a matching approval for the same client and user is the only open one. That residual is low risk: it requires a live approval of this exact server for that client and user, and any other open resource, including an open approval with no resource, leaves the token unbound.
4. Confirm the bucket is private and the file size limit is 25 MiB. Content blobs are stored at `{user_id}/{sha256}`. Client uploads land at `{user_id}/incoming/{nonce}` and engine output lands at `{user_id}/stage/{uuid}` until the server copies them onto the content key. The service role stays on the MCP server. Clients and the engine use 15-minute signed URLs.
5. Set `STETWISE_STORE` unset (or anything other than `local`) on the host so the server uses this adapter. Keep `STETWISE_STORE=local` for laptops and tests.
6. Schedule purge at least once an hour. Vercel Cron calls `GET /internal/purge` with `Authorization: Bearer $CRON_SECRET`. `POST /internal/purge` with header `x-stetwise-purge: $STETWISE_PURGE_SECRET` remains. Expired files, expired proposals, and blobs nothing references are removed. In-progress `incoming/` and `stage/` objects younger than 2 hours are kept. Default retention is 24 hours after last use. `set_retention` can set 168 hours.

`profiles.id` references `auth.users`. Dev auth (`STETWISE_DEV_AUTH`) is for the local store only.

## Hosting

Vercel serves the MCP and account pages. The engine is a separate container: Vercel at 2 vCPU and 4 GB, with Fly.io as the fallback. Supabase holds accounts and the private bucket. File bytes do not pass through Vercel. A request body there is capped at 4.5 MB, and base64 of a 25 MB file is far larger than that.

```text
assistant --JSON--> Vercel (MCP, auth, account pages, maxDuration 300)
client    --PUT/GET--> Supabase Storage signed URLs (15 minutes)
Vercel    --HMAC timestamp + nonce--> engine container
engine    --signed URL--> Supabase Storage (fetch and write)
Vercel    --service role--> Postgres, sign, and copy
```

Hosted `start_upload` returns a signed PUT URL for `{owner}/incoming/{nonce}`. The client uploads straight to Storage, then calls `complete_upload`. The engine reads that object, and the server copies it to `{owner}/{sha256}`. `export` returns a signed GET URL. Propose, apply, recalc, and import pass signed URLs and object keys. The engine fetches and writes Storage itself. The MCP server does not put file bytes in the engine JSON.

The engine signs `timestamp.nonce.body` with `ENGINE_HMAC_SECRET`. Requests older than 5 minutes, and reused nonces, are rejected. The nonce cache is in memory on each engine process. `STETWISE_ENGINE_MAX_BODY` defaults to 4 MiB. CPU work runs in a process pool (`STETWISE_ENGINE_CONCURRENCY`, default 2). `/health` does not wait on that pool. The engine reads `PORT` and defaults to 8080.

`vercel.json` uses the functions and rewrites form. `src/server.ts` has `maxDuration` 300. An hourly cron hits `GET /internal/purge`. Set `STETWISE_ACCEPT_UPLOADS=0` on Vercel so a stray `/v1/upload` is refused.

Local and dev leave `ENGINE_URL` unset. `start_upload` and `export` then use `/v1/upload` and `/v1/download` on this Node process, and the engine sees base64. That path is what tests use.

The engine is not a public client. It accepts only those signed requests. It does open outbound connections: to the Storage URLs in the request, and to an attachment URL the MCP server has already checked. Vercel and Fly.io cannot enforce a no-outbound policy, so that is not a guarantee. File contents are not logged. Do not give the engine the service role key.

Do not deploy from this repository. Do not create Stripe products or prices. Checkout only references `STRIPE_PRODUCT_ID`, `STRIPE_PRICE_MONTHLY`, and `STRIPE_PRICE_YEARLY`.

## What works in v1

- Inspect, read a range or section, and search `.xlsx`, `.xlsm`, and `.docx`.
- `propose_edit` then `apply_edit` for `set_cells` (including Excel table body cells and shared formulas), `clear_range`, `fill_range`, `insert_rows`, `insert_cols`, Excel `replace_text` on text values, `format_cells` (number format, bold, italic, fill, alignment, column width, font size, font colour, and a thin border), Word `replace_text`, `replace_paragraph`, `update_table_cells`, `insert_paragraph` (including a paragraph style already defined in the document, such as Heading 1–3 or a list style on a new document), `delete_paragraph`, and `format_runs` (bold, italic, underline, font size, and font colour on the run only). One proposal can touch at most 5000 cells.
- `create_file` for a blank `.xlsx` or `.docx`, then the same propose and apply flow.
- `list_comments` to read Word comments without changing the file.
- `recalculate` runs LibreOffice's Calc engine on a copy and previews cached formula values. Results may differ from Excel on edge cases. Dates, currency, and percents stay numbers. Booleans, errors, and strings keep their own cell types. A LibreOffice error that is not an Excel error value is refused, and nothing is written. Apply that proposal to keep the cached values. Undo restores the previous bytes. The current head is cached between propose and apply, and dropped when the file expires or is deleted.
- Word edits are direct when tracking is off. Pass `track_changes: true`, or edit a document that already has tracking on, and the same change is written as `w:ins` / `w:del` by Stetwise.
- Versions, undo, and a signed download link.
- ChatGPT file import (`import_file`) and a signed upload link for other clients. Hosted clients call `complete_upload` after the PUT.
- OAuth metadata, consent, Stripe Checkout with a 14-day trial that does not require a card (`payment_method_collection=if_required`, missing payment method cancels at the end of the trial), and the billing portal. Same account shape as Continuity.
- Byte-level refusal when a workbook or document cannot be edited safely. Untouched zip entries are copied with their original compressed bytes.

## Refused by design

- Edits of several files in one call.
- Legacy `.xls`, `.doc`, and `.ppt`, and encrypted or IRM files.
- Running macros. `vbaProject.bin` is copied and never executed.
- PowerPoint is a separate format. Placeholder and master slides would break the byte-for-byte proof, so v1 says Excel and Word.
- Creating or rewriting pivot tables, chart XML, or slicers. Those parts stay byte-for-byte identical.
- Excel table header rows, totals rows, and `table.xml`. Body cells can change.
- Protected sheets and workbooks, and the non-origin cell of a merge.
- Inserting rows or columns when the workbook has pivots, charts, drawings, tables, shared formulas, 3D references, macros, comments, or protection.
- A shared formula whose master formula is missing. v1 will not invent it. A solid row or column can shrink or promote a neighbor; a cell in the middle is unshared into explicit formulas.
- Word edits while the document is protected.
- Rewriting an existing tracked change, or accepting and rejecting someone else's revisions.
- Rewriting comments, headers, footers, footnotes, endnotes, `word/styles.xml`, or the theme. `list_comments` is read-only. `insert_paragraph` can select a paragraph style that already exists, including a heading or list style, and will not create or edit one. `format_cells` and `format_runs` append or set direct formatting and leave the theme alone.
- Excel `replace_text` on formula text. Only cached text values change, and `sharedStrings.xml` stays byte-for-byte identical.
- PDF or PNG previews.
- Private, loopback, and link-local download URLs.
- Google Drive, OneDrive, and local disk access beyond the signed upload link.

## Known gaps

- `supabase/schema.sql` is applied by you in the Supabase SQL editor. This repository does not create the project.
- No Excel-saved golden file for row insert. The shifter follows Excel's reference rules and is tested on the hand-built model.
- Formula edits clear the cached value and set `fullCalcOnLoad` unless you call `recalculate`, which patches LibreOffice values from a copy. Chart caches and pivot caches are not refreshed.
- The engine accepts HMAC-signed requests from the MCP server (timestamp, nonce, 5-minute window). It fetches and writes the Storage objects those requests name. Vercel and Fly.io cannot enforce a no-outbound policy. Require `ENGINE_HMAC_SECRET`. File contents are not logged.
- DNS rebinding between the address check and the connection is still possible. Hosts that resolve to private addresses are refused at check time.
- `openpyxl` is not used. Whole-workbook saves drop shapes and pivots, so edits stay at the package and XML part.
- `npm run benchmark` writes `BENCHMARKS.md` with CPU time and peak memory for inspect, propose, apply, restore, and recalculate. Those numbers are from the machine that ran the script. `python3 scripts/benchmark.py --recalc-only` refreshes only the recalculate section.
